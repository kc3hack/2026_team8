# チーム名
**HaxSoft**

## 背景・課題・解決されること

### **背景・課題：チャットを続けることによる精度の低下**
ChatGPTやGeminiなどの対話型AIを利用している際、ある回答（A）の中に気になるトピック（A1, A2...チャットで深掘りを続けると、AIの性能低下という課題が発生します。

#### **1. UXの悪化**
本筋（A、B、C）に関係のない寄り道（A1, A2...）の会話が間に挟まることで、後から必要な情報を探し出したり、前の文脈をさかのぼることが困難になります。また、深掘りに集中するあまり当初の目的を忘れてしまう、あるいは履歴が長すぎて見返す気を失ってしまうといった課題が生じます。

#### **2. AIモデルの性能劣化（技術的背景）**
最新のAIであっても、一つのチャットが長大化すると、AIが文脈の中間部分の情報を正しく処理できなかったり、ノイズ増加によって回答が不正確になったりします。

### **解決：Gitから着想を得たチャット（ブランチ/マージ）**
この人間とAIの両方の課題を解決するために生まれたのが「**yorimichi**」です。
Gitのブランチ/マージの概念をチャットに導入することで、不必要な履歴をチャットに残さず、文脈が整理されたツリー状で管理できるようにしました。

これにより、必要な情報のみ参照でき、AIの精度を落とさないようなシステムを実現しています。

## プロダクト説明
**yorimichi** は、Gitでブランチを切るように、会話を派生することができるAIチャットアプリです。

- **ブランチ（ヨリミチ）**: 会話の途中からブランチを切り（ヨリミチ）、並列でチャットができます。
- **文脈の継承**: 派生したブランチは、それまでの会話内容（親ブランチの履歴）を完全に理解した状態でチャットができます。
- **マージとクリーンアップ**: 並列で行った思考の結果をメインの会話にマージしたり、不要になったブランチ（ヨリミチ）を削除したりできます。

「“本当に欲しい”をカタチに」というテーマに対し、AIとの対話を「一直線のやり取り」から「並列的な思考プロセス」へと進化させることで応えます。

### 操作説明
1. **メインチャット**: 通常通りのAIチャットでアイデアを広げます。
2. **ヨリミチ**: 特定の返答から深掘りしたい時、メッセージ右下の？ボタンで新しい「ヨリミチ」を作ります。
3. **並列探索**: ヨリミチは並列に増やすことができ、それぞれ自由に質問や会話をできます。
4. **合流**: 良い回答やコードが得られたら、チェックマークでメインの履歴に成果を反映させます。

## 注力したポイント

### アイデア・デザイン面
- **Gitを意識させないUI**: Gitを知らない人でもヨリミチの感覚で理解できる仕組みを考案しました。
- **チャットの純度**: 会話をブランチに閉じ込めることで、メインブランチには常に洗練された結論だけを残せるようにしました。
- **モダンなUI**: 直感的に理解でき、最低限の情報量だけを表示するようにしました。

### 技術面
- **高度な文脈管理**: Vercel AI SDKとGemini APIを組み合わせ、複雑な分岐構造を持つデータモデル（Prisma / Supabase）との整合性を保ちながら、ストレスのないストリーミング応答を実現しました。
- **柔軟なウィンドウシステム**: 画面幅に合わせて快適にマルチチャットを表示・操作できるレスポンシブな設計にしました。
